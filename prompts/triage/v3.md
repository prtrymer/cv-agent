role_family — the kind of engineer the posting really hires, judged by the core daily work, not by buzzwords:
- fullstack: owns features across browser UI and server side.
- frontend: mostly browser UI (React, Angular, Vue, Next.js and the like).
- backend: server side in TypeScript / JavaScript (Node.js, NestJS, Express).
- java: server side on the JVM in Java (Spring, Jakarta EE). A Kotlin-first or Scala-first role is other.
- other: anything else — Python, Go, .NET, PHP or Ruby backends, mobile, data, ML, DevOps, QA, management.

Score 0–100 = how likely this candidate passes the first screening for THIS role, using only the CANDIDATE PROFILE below:
- 85–100: core stack and domain match; seniority within reach.
- 70–84: strong stack match with small misses (a nice-to-have missing, an adjacent framework).
- 55–69: plausible but stretched (one core technology missing, or seniority clearly above).
- 0–54: wrong role family, a must-have primary language or platform the candidate never used, or location/eligibility he cannot meet.

Rules:
- A technology counts as matched only if the profile lists it. Never assume.
- "Senior" titles are fine when the stack matches.
- Years: the candidate applies to roles asking for up to {{years_ok}} years — overall or for a technology he has used commercially — so such asks never lower the score and are never blockers. Only an ask above {{years_ok}} years counts against him: up to 2 years above lowers the score, more than that is a hard blocker. A technology he never used is still judged as missing, whatever the years.
- location_ok: false when the role needs on-site or hybrid presence outside the candidate's commute cities, or restricts remote work to a country other than Czechia; true otherwise, including when unclear.
- hard_blockers: only true deal-breakers, as short noun phrases ("primary language Kotlin", "on-site in Kyiv"). Empty when none.
- matched_requirements: requirements from the posting the candidate genuinely meets, paraphrased briefly.
- lead_with: up to 3 engagement ids from the profile that best evidence the fit for this role family, strongest first.
- salary: the posted range if the posting states one (numbers as written, currency code such as USD/EUR/CZK/UAH, period month/year/hour), else null.
- posting_language: the main language of the posting text.
